# Benchmarking Framework Proposal: HDF5 + Python + R

**Date:** 2026-03-31

**Status:** Proposal (not yet implemented)

**Purpose:** Design a robust, scalable benchmarking infrastructure that:

- Avoids merge contamination issues
- Uses scientific-grade statistical analysis (R)
- Handles large-scale experiments efficiently (HDF5)
- Maintains human-readable outputs (CSV)
- Is heavily documented for accessibility

---

## Executive Summary

Current benchmarking approach has architectural limitations:

1. Benchmarking code in core solver C++ causes merge conflicts
2. Statistical calculations duplicated in Python/C++
3. JSON inefficient for large datasets
4. No proper R-based statistical rigor

**Proposed solution:** Three-layer architecture:

- **C++ harness** (minimal): Just collect raw data
- **Python orchestration** (efficient storage): Stream to HDF5 + export human-readable CSV
- **R analysis** (statistical rigor): Load HDF5, calculate metrics, generate reports

---

## Problem Statement

### Current Issues

1. **Merge contamination:** `mac-dev-benchmark-enhancements` repeatedly merges flat_cache/refactor-caching unintentionally
   - Root cause: Benchmarking code in core solver makes it hard to isolate

2. **Duplicated statistics:** Geometric mean, PAR2, NPS calculations in both C++ and Python
   - Creates divergence between branches
   - Hard to fix one place without fixing both
   - Fragile custom implementations

3. **Data format limitations:** JSON is text-based and memory-inefficient
   - 1000 runs in JSON: ~5-10 MB
   - Doesn't stream well
   - No metadata structure

4. **Missing rigor:** Python `statistics` module is basic
   - No confidence intervals, hypothesis tests, sensitivity analysis
   - Not publication-ready
   - No established best practices

## Component Design

### 1. C++ Harness (`benchmarking/harness.cpp`)

**Purpose:** Minimal executable that runs solver N times on a single instance

**Input:** Command-line arguments
```bash
./harness \
  --instance tests/resources/level1/klondike/klondike_001.json \
  --iterations 3 \
  --warmup 1 \
  --timeout 60000 \
  --output results.json
```

**Output:** JSON with raw metrics (no statistics)
```json
{
  "metadata": {
    "instance": "klondike_001",
    "date": "2026-03-31T14:32:00Z",
    "timeout_ms": 60000
  },
  "runs": [
    {
      "time_us": 1234.56,
      "nodes": 50000,
      "solution_type": "SOLVED",
      "memory_bytes": 104857600,
      "unique_nodes": 45000,
      "backtracks": 1000,
      "dominance_moves": 500
    },
    ...
  ]
}
```

**Key principle:** Harness does ONE thing—collect raw data. No statistics, no aggregation.

---

### 2. Python Orchestration (`experiments/run_experiment.py`)

**Purpose:** Coordinate running harness on all instances, manage data

**Responsibilities:**

- Read YAML experiment config
- Loop over instances
- Call C++ harness
- Stream results to HDF5
- Generate CSV export automatically
- Log all activity

**Pseudocode:**

```python
def run_experiment(config):
    # Create HDF5 file with metadata
    with h5py.File(f"exp_{date}.h5", "w") as h5:
        write_metadata(h5, config)
        init_datasets(h5)

        # Loop over instances
        for instance in config['instances']:
            # Call C++ harness
            result = subprocess.run([
                'benchmarking/harness',
                '--instance', instance['path'],
                '--iterations', config['iterations'],
                '--timeout', config['timeout_ms']
            ])

            # Parse result JSON
            data = json.load(result.stdout)

            # Append to HDF5 (streaming - efficient)
            append_to_hdf5(h5, data)

    # Export to CSV (automatic)
    export_hdf5_to_csv(f"exp_{date}.h5", f"exp_{date}.csv")

    # Optional: export to JSON
    if config.get('export_json'):
        export_hdf5_to_json(f"exp_{date}.h5", f"exp_{date}.json")
```

**Benefits:**

- ✅ Data streamed to disk (no memory bloat)
- ✅ Can resume interrupted experiments
- ✅ Automatic CSV generation (human-readable)
- ✅ Logging of what happened

### 3. HDF5 Schema

**File structure:**

```
exp_2026_03_31.h5

/metadata/                          (experiment info)
  experiment_name: str
  description: str
  date_created: ISO timestamp
  researcher: str
  instances_path: str
  instance_count: int
  iterations_per_instance: int
  timeout_ms: int
  hardware_cpu: str
  hardware_ram_gb: float

/baseline/                          (baseline solver results)
  metadata/
    solver_version: str (e.g., "v2.1")
    solver_commit: str (7-char hash)
    streamliner: str (none|auto-foundations|suit-symmetry|both|smart)
    cache_capacity_bytes: int

  runs/                            (raw results, all concatenated)
    time_us: [1234.5, 5678.9, ...]     (shape: 450 = 150 instances × 3 runs)
    nodes: [50000, 75000, ...]
    solution_type: ["SOLVED", "SOLVED", "TIMEOUT", ...]
    memory_bytes: [104857600, 209715200, ...]
    unique_nodes: [45000, 70000, ...]
    backtracks: [1000, 2000, ...]
    dominance_moves: [500, 1000, ...]

  aggregates/                      (per-instance summary)
    instance_name: ["klondike_001", "klondike_002", ...]
    mean_time_us: [1234.5, 5500.2, ...]
    median_time_us: [1200.0, 5400.1, ...]
    stdev_time_us: [100.5, 200.3, ...]
    solved_count: [3, 3, 3, ...]    (how many runs solved)

/current/                           (current solver results - same structure)
  metadata/
    solver_version: str
    solver_commit: str
    ...
  runs/
    time_us: [...]
    nodes: [...]
    ...
  aggregates/
    ...
```

**Size estimates:**

- 150 instances × 3 runs = 450 total runs
- Per run: ~8 numbers × 8 bytes = 64 bytes
- Total data: 450 × 64 = 28.8 KB
- With metadata + compression: ~50-100 KB per experiment
- 10,000 runs: ~500 KB-1 MB

**vs JSON:** Same data in JSON would be ~5-10 MB (100x larger)

### 4. R Analysis (`analysis/analyze_experiment.R`)

**Purpose:** 

Load HDF5, calculate rigorous statistics, generate report

**Key functions:**

```r
# Load and compare experiments
analyze_comparison <- function(h5file) {
  baseline <- read_h5_group(h5file, "/baseline/runs")
  current <- read_h5_group(h5file, "/current/runs")

  # Calculate statistics (using established R methods)
  baseline_stats <- calculate_stats(baseline$time_us)
  current_stats <- calculate_stats(current$time_us)

  # Statistical test (Wilcoxon signed-rank - appropriate for time data)
  test <- wilcox.test(baseline$time_us, current$time_us)

  # Generate report
  generate_report(baseline_stats, current_stats, test)
}

# Calculate rigorous statistics
calculate_stats <- function(times) {
  list(
    mean = mean(times),
    median = median(times),
    sd = sd(times),
    geomean = exp(mean(log(times))),  # Proper geometric mean
    se = sd(times) / sqrt(length(times)),
    ci_lower = quantile(times, 0.025),
    ci_upper = quantile(times, 0.975),
    min = min(times),
    max = max(times)
  )
}
```

**Output:** HTML report with embedded plots, tables, statistical summary

## Data Format Comparison

| Aspect | JSON | CSV | HDF5 |
|--------|------|-----|------|
| **Size (1000 runs)** | 5-10 MB | 2-3 MB | 50-100 KB |
| **Human readable** | Yes | Yes | No (binary) |
| **Read entire file** | Yes (memory) | Line-by-line (streaming) | Chunk-by-chunk (efficient) |
| **Metadata** | Possible (verbose) | Limited (header comments) | Built-in, structured |
| **Nested structure** | Yes | Flat | Yes (groups/datasets) |
| **R support** | Via jsonlite | Native (read.csv) | Via rhdf5 |
| **Default for users** | ❌ | ✅ CSV exported automatically | ❌ Primary storage |

**Recommendation:**

- **Storage:** HDF5 (primary - efficient, searchable, future-proof)
- **Human-readable:** CSV (auto-exported - can open in Excel)
- **Optional:** JSON (for compatibility, on request)

- Resume capability (if interrupted, restart from last instance)

## Benefits & Trade-offs

### Benefits

✅ **Eliminates branch contamination:** Benchmarking code separate from core solver
✅ **Rigorous statistics:** Use R's established methods, not custom implementations
✅ **Efficient storage:** HDF5 ~100x smaller than JSON
✅ **Human-readable:** CSV exported by default
✅ **Reproducible:** All metadata embedded (commit, date, hardware, config)
✅ **Scalable:** Can handle 100k+ runs without memory issues
✅ **Documented:** Clear separation of concerns

### Trade-offs

❌ HDF5 requires `libhdf5` and R `rhdf5` package (easy to install)
❌ Binary format not human-readable (but CSV available)
❌ Requires R for analysis (establishes dependency, but worth it)
❌ Python orchestration adds one more language

## Questions for Discussion

1. **HDF5 vs Parquet?** HDF5 is more established in scientific computing. Parquet better for big data analytics. Either works.

2. **R vs Python stats?** R is scientific standard, but adds dependency. Could use SciPy for stats if R unacceptable.

3. **Separate harness binary?** Proposed approach creates `benchmarking/harness` separate from main `solvitaire`. Alternative: use main binary with `--benchmark` flag. Separate is cleaner.

4. **Large experiment framework?** For truly massive studies (1M+ runs), might want database backend (SQLite/PostgreSQL). Deferred to Phase 4.
